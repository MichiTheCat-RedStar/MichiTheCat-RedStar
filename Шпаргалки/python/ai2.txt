	--- ЧТО ТАКОЕ ИИ ---
 = Суть:
- Определение:
ИИ - это параметрическая модель, которая подбирает числа (веса),
чтобы её ошибка на данных становилась меньше


- Что важно понимать:
Модель не "думает" как человек
Она отображает вход в выход через набор весов
Обучение = подбор весов, а не запись правил


- Три уровня сложности:
1. Бинарный поиск			# правило известно заранее
2. Одно обучаемое число		# линейная зависимость
3. Много чисел (нейросеть)	# сложная зависимость


- Что НЕ является обучаемым ИИ:
if/else						# жёсткие правила
regex						# шаблоны без подбора весов
hash / dict lookup			# прямой поиск
sort / binary search		# алгоритмы, не обучение


- Где ИИ уместен:
когда правила неизвестны или слишком сложны
когда есть примеры входа и выхода
когда допустимы ошибки и нужна оценка качества
когда закономерности важнее явных условий


 = Чем ИИ отличается от обычной программы:
- Программа:
логика задана человеком
результат детерминирован при тех же входных данных
ошибки обычно в коде или спецификации


- Обучаемая модель:
логика выражена весами
результат зависит от данных и обучения
ошибки измеряются статистически, не только assert'ами


- Практический вывод:
Для ИИ нужны данные, метрика, сплит и проверка
Без этого это просто код с непонятным поведением



	--- ОБУЧЕНИЕ ОДНОГО ЧИСЛА ---
 = Линейная модель без смещения:
- Формула:
y = w * x


- Полный цикл обучения:
guess = w * x						# предсказание
error = target - guess				# ошибка: положительная значит недооценили
w += lr * error * x					# подкрутка веса


- Смысл словами:
Ошибся в плюс — сдвинь w вверх
Ошибся в минус — сдвинь w вниз
Сдвинь не на всю ошибку, а на маленькую часть (lr)
Чем больше вход x — тем сильнее рычаг


- Проверка знака:
Если target > guess, error > 0, w растёт при x > 0
Если target < guess, error < 0, w падает при x > 0
Если x отрицательный, влияние веса инвертируется


 = Линейная модель со смещением:
- Формула:
y = w * x + b


- Полный цикл:
guess = w * x + b
error = target - guess
w += lr * error * x
b += lr * error


- Зачем bias:
Позволяет модели иметь nonzero output при x = 0
Без bias прямая всегда проходит через ноль


- Практика:
bias обычно учат вместе с w
lr для bias можно делать таким же или меньше


 = Loss и градиент:
- Ошибка:
error = target - guess


- Квадратичная потеря:
loss = error * error


- Почему квадрат:
Большие ошибки штрафуются сильнее
Градиент гладкий и простой


- Связь с обновлением:
Для loss = (target - w * x) ** 2:
dloss/dw = -2 * error * x
w -= lr * dloss/dw
То есть w += 2 * lr * error * x
Константу 2 часто сворачивают в lr


 = Бинарный поиск как частный случай:
- Идея:
guess = 50							# начальная догадка
подсказка = target - guess			# числовая ошибка
guess += lr * подсказка				# сдвиг к правильному


- Отличие от обучения:
В поиске правило известно (диапазон)
В обучении правило неизвестно, находится по примерам


- Когда полезно:
если есть прямой сигнал "ближе/дальше"
если можно мерить ошибку численно
если нужно объяснить идею градиентного спуска просто


 = Типичные проблемы одного веса:
- w не сходится:
lr слишком большой				# значения прыгают, loss растёт
lr слишком маленький			# обучение почти не идёт
данные противоречивы			# одинаковый x даёт разный target
нет bias, а данные не через ноль


- w сходится медленно:
мало эпох
слабые признаки
входы не масштабированы
начальное w далеко от решения


- Как диагностировать:
печатай loss каждые N шагов
смотри знак error
проверяй, что target и guess одного масштаба
попробуй lr 0.1, 0.01, 0.001



	--- СПАМ-ФИЛЬТР (МНОГО ЧИСЕЛ) ---
 = Идея:
Каждое слово = один вес w
Сумма весов слов письма + bias > threshold → спам
Обучение подкручивает веса так, чтобы спам-слова имели больший вес


- Почему это уже модель:
Правила никто не писал явно
Вес слова появляется из статистики примеров
Модель можно оценить, переобучить, улучшить признаками


 = Токенизация:
- Базовая:
import re


def tokenize(text: str) -> list[str]:
    return re.findall(r"[а-яёa-z0-9]+", text.lower())


- Что делает:
Приводит к нижнему регистру
Выбрасывает пунктуацию
Разбивает на слова/цифры


- Важно:
Токенизатор должен быть одинаковым для обучения и проверки
Лучше сохранять список токенов, чем пересчитывать каждый раз
Для реальных задач учитывай Unicode, эмодзи, код, URL, цифры


 = Признаки (features):
- Bag of words:
features = {word: 1 for word in set(tokenize(text))}


- Count vector:
from collections import Counter
counts = Counter(tokenize(text))


- Разница:
set: слово влияет один раз
Counter: частые слова влияют сильнее


- Для начала:
Используй set, проще и устойчивее к длине письма
Потом можно добавить частоты, n-grams, длинные признаки


 = Предсказание:
- Счёт:
def score(text: str, weights: dict[str, float], bias: float = 0.0) -> float:
    tokens = set(tokenize(text))
    return bias + sum(weights.get(word, 0.0) for word in tokens)


- Решение:
def predict(text: str, weights: dict[str, float], bias: float = 0.0, threshold: float = 0.0) -> int:
    return 1 if score(text, weights, bias) > threshold else 0


- Смысл:
score > 0 → скорее спам
score < 0 → скорее не спам
threshold можно двигать, менять баланс precision/recall


 = Обучение:
- Простой Perceptron:
lr = 0.1
bias = 0.0
weights = {}


for epoch in range(20):
    for text, label in data:
        pred = predict(text, weights, bias)
        err = label - pred				# -1, 0 или +1
        if err != 0:
            tokens = set(tokenize(text))
            for word in tokens:
                weights[word] = weights.get(word, 0.0) + lr * err
            bias += lr * err


- Что происходит:
Спам-слово встречается часто → вес растёт
Нейтральное слово → вес падает
Ошибочные слова получают корректировку


- Ограничение:
Perceptron сходится только если данные линейно разделимы
Для реальных данных лучше logistic regression / neural net


 = Logistic regression (мягче):
- Идея:
p = sigmoid(score)
loss = -(y * log(p) + (1 - y) * log(1 - p))


- Обновление:
err = y - p
weights[word] += lr * err * feature
bias += lr * err


- Почему лучше:
Не требует жёсткой разделимости
Даёт вероятность, а не только 0/1
Можно настраивать порог
Устойчивее к шуму в данных


 = Оценка качества:
- Accuracy:
acc = correct / total


- Precision:
precision = TP / (TP + FP)			# насколько точны предсказания "спам"


- Recall:
recall = TP / (TP + FN)				# сколько спама поймали


- F1:
f1 = 2 * precision * recall / (precision + recall)


- Confusion matrix:
TN FP
FN TP


- Важно:
При дисбалансе классов accuracy может врать
Для спама обычно важнее precision + recall, чем просто accuracy
Порог decision boundary можно подбирать по валидации


 = Риски и улучшения:
- Переобучение:
Модель запоминает редкие слова
Лечение: больше данных, regularisation, min word frequency


- Дисбаланс классов:
Спамов мало, accuracy высокая при "всегда не спам"
Лечение: взвешенная loss, stratified split, метрики precision/recall


- Атаки:
Спам-слова могут обходить фильтр
Лечение: нормализация, устойчивость к символам, ансамбли


- Признаки:
Добавляй длину письма, наличие ссылок, cap ratio, digits, special chars
Используй n-grams, если слов недостаточно
Следи за утечкой данных: train/val/test должны быть независимы



	--- СКРЫТЫЙ СЛОЙ (MLP) ---
 = Зачем:
Линейная модель ловит только прямые зависимости
Скрытый слой ловит нелинейные (XOR, изгибы, пороги)
MLP = несколько линейных слоёв + нелинейные активации


- Простой смысл:
Первый слой строит признаки
Второй слой комбинирует признаки
Активация добавляет нелинейность
Без активации несколько слоёв схлопнутся в один линейный


 = Формула прямого прохода:
- Обозначения:
X = вход, shape (N, in_features)
W1 = веса первого слоя, shape (in_features, hidden)
b1 = смещение первого слоя, shape (hidden)
a1 = активация после первого слоя
W2 = веса второго слоя, shape (hidden, out_features)
b2 = смещение второго слоя
z2 = логиты
p = вероятности


- Слои:
z1 = X @ W1 + b1						# скрытый слой
a1 = relu(z1)							# активация
z2 = a1 @ W2 + b2						# выход
p = softmax(z2)							# вероятности классов


- Для бинарной классификации:
p = sigmoid(z2)							# одна вероятность класса 1
loss = BCEWithLogitsLoss(z2, y)			# стабильнее, чем sigmoid + BCE


 = Активации:
relu(x) = max(0, x)							# простое и рабочее
leaky_relu(x) = x if x > 0 else 0.01*x		# меньше "мёртвых нейронов"
sigmoid(x) = 1 / (1 + exp(-x))				# для бинарной классификации
tanh(x) = (exp(x)-exp(-x))/(exp(x)+exp(-x)) # выход в [-1,1]
softmax(x) = exp(x) / sum(exp(x))			# для многоклассовой
gelu(x) = x * Phi(x)						# часто в трансформерах
silu(x) = x * sigmoid(x)					# Swish, популярна в LLM


- Практика:
Для скрытых слоёв чаще ReLU/LeakyReLU/GELU/SiLU
Для выхода классификации: softmax или sigmoid
Не ставь softmax перед loss, если loss принимает logits
Для регрессии выход обычно без активации или с clamp


 = Backward (цепное правило):
- Для softmax + cross entropy:
dz2 = (p - onehot(y)) / N				# средний градиент по батчу
dW2 = a1.T @ dz2
db2 = dz2.sum(axis=0)
da1 = dz2 @ W2.T
dz1 = da1 * (z1 > 0)					# производная ReLU
dW1 = X.T @ dz1
db1 = dz1.sum(axis=0)


- Для sigmoid + BCE:
dz2 = (p - y) / N


- Смысл:
Ошибка на выходе распространяется назад
Каждый вес получает вклад в ошибку
Градиент показывает, в какую сторону крутить вес


 = Шаг градиентного спуска:
W1 -= lr * dW1
b1 -= lr * db1
W2 -= lr * dW2
b2 -= lr * db2


- Знак:
Если используешь error = target - prediction и обновление +=,
то это эквивалентно спуску с другим знаком градиента
В PyTorch обычно loss.backward() и optimizer.step() делают спуск сами


 = Инициализация весов:
- Нельзя:
W = zeros						# все нейроны одинаковые, градиенты симметричны


- Можно:
small random normal/uniform
Xavier/Glorot для tanh/sigmoid
He/Kaiming для ReLU


- Пример He:
std = sqrt(2 / fan_in)
W ~ Normal(0, std)


- Bias:
обычно zeros
иногда можно small positive для ReLU, но чаще не нужно


 = Batch, epoch, step:
- Epoch:
один проход по всему датасету


- Batch:
подмножество данных для одного обновления


- Step:
одно обновление весов на одном батче


- Mini-batch SGD:
for epoch in range(epochs):
    shuffle data
    for batch in loader:
        optimizer.zero_grad()
        logits = model(x)
        loss = criterion(logits, y)
        loss.backward()
        optimizer.step()


- Зачем batch:
быстрее, стабильнее, использует векторизацию/GPU
меньший batch шумнее, больший batch стабильнее, но ест память


 = Регуляризация и dropout:
- L2 weight decay:
W -= lr * (grad + lambda * W)
Штрафует большие веса


- Dropout:
Во время обучения случайно зануляет часть нейронов
Во время inference не применяется или масштабируется
Лечит переобучение


- Early stopping:
Останавливай обучение, когда val loss перестаёт падать
Сохраняй лучшую модель по валидации, а не по train


 = Архитектурные подсказки:
- Слишком мало слоёв:
недообучение, модель не ловит нелинейность


- Слишком много слоёв/нейронов:
переобучение, медленнее, сложнее оптимизировать


- Нормализация:
BatchNorm/LayerNorm могут стабилизировать обучение
Но для простых MLP часто можно без них


- Остаточные связи:
help deeper networks
в маленьких MLP избыточны



	--- ОТЛАДКА ОБУЧЕНИЯ ---
 = Модель не учится:
- Симптомы:
loss не падает
loss NaN
train падает, val растёт
accuracy 100% но плохо на новых
predictions always same class


- Проверки:
lr слишком большой/маленький
данные не нормализованы
labels перепутаны
features constant
shapes не совпадают
weights initialized zeros
градиенты не считаются
optimizer не применяет step
batch size = 0 или dataset empty


 = Loss NaN/Inf:
- Причины:
lr слишком большой
переполнение exp/softmax
деление на ноль
логиты слишком большие
входы не масштабированы
логарифм от нуля/отрицательного


- Лечение:
уменьшить lr
clip gradients
stable softmax: вычитать max перед exp
BCEWithLogitsLoss / CrossEntropyLoss from logits
normalize inputs
добавить eps в log
проверять target dtype для classification


 = Переобучение:
- Признаки:
train loss ↓, val loss ↑
модель запоминает шум
слишком много параметров для данных
метрики на train идеальные, на test плохие


- Лечение:
больше данных
упростить модель
dropout
weight decay
early stopping
data augmentation
cross-validation
feature selection


 = Недообучение:
- Признаки:
train и val loss высокие
модель слишком простая
мало эпох
lr плохой
признаки неинформативные


- Лечение:
больше ёмкости
больше эпох
подбор lr
лучшие признаки
нелинейность
нормализация данных


 = Дисбаланс классов:
- Проблема:
99% нормальных, 1% аномалий
модель всегда предсказывает нормальный
accuracy высокая, но пользы нет


- Метрики:
accuracy бесполезна
используй precision, recall, F1, ROC-AUC, PR-AUC
смотри confusion matrix


- Лечение:
class weights
oversampling/undersampling
threshold tuning
anomaly detection framing
collect more minority data


 = Воспроизводимость:
- Фиксируй:
seed: random, numpy, torch
версии библиотек
конфиг обучения: lr, batch, epochs, optimizer
путь к данным и сплитам
метрики и лучшие checkpoint'и


- Важно:
GPU/CPU могут давать чуть разные результаты
dataloader workers могут влиять на порядок
полная детерминированность иногда стоит скорости

	--- ПРАКТИЧНЫЕ ИДЕИ БЕЗ ЖЕЛЕЗА ---
 = Текстовые мини-проекты:
- Спам-фильтр:
Вход: текст, выход: 0 или 1
Метрики: precision, recall, F1


- Определитель языка:
Вход: короткая фраза, выход: код языка
Признаки: n-grams, символы, частоты букв


- Тональность отзывов:
Вход: отзыв, выход: хорошо/нейтрально/плохо
Осторожно с sarcasm и контекстом


- Классификатор интентов:
Вход: сообщение, выход: команда/вопрос/жалоба
Полезно для ботов и CLI


- Next word model:
Вход: последние N слов, выход: следующее слово
Можно начать с Markov chain, потом MLP


 = Числовые мини-проекты:
- Линейная регрессия:
Вход: площадь, комнаты, этаж
Выход: цена
Проверь MSE, R^2


- Прогноз следующего значения:
Вход: текущее значение + скорость
Выход: значение через N шагов
Хорошо для датчиков


- Детектор аномалий:
Вход: датчики
Выход: норма/аномалия
Идея: ошибка предсказания > порог


- Калибровка датчика:
Вход: сырое значение
Выход: исправленное значение
Линейная модель может хватить


 = Игровые мини-проекты:
- Крестики-нолики:
Вход: доска 3x3
Выход: лучший ход
Можно обучать через игру против себя


- Простой Q-learning:
Вход: состояние
Выход: ценность действий
Обновление: target = reward + gamma * max(next_values)


- Классификация жестов:
Вход: акселерометр
Выход: влево/вправо/вверх
Нужны окна данных и нормализация


 = Важное предупреждение:
Если задача решается if/else — не усложняй
ИИ нужен, когда правила неизвестны, громоздки или меняются
Без данных и метрики обучение превращается в гадание



	--- СВЯЗЬ С LLM И НЕЙРОСЕТЯМИ ---
 = Что общего:
LLM тоже минимизирует ошибку предсказания следующего токена
Веса подобраны на огромных данных
Базовая идея та же: forward / loss / backward / update
Transformer — это MLP + attention + position encoding + нормализация


 = Что отличается:
LLM обычно не обучаются на слабом ноутбуке
Инференс ≠ обучение
Prompt tuning / fine-tuning / LoRA — разные уровни доступа к весам
Context window, tokenizer, chat template становятся критичными
Качество сильно зависит от данных, разметки и оценки


 = Практический вывод:
Понял один вес → понял градиент
Понял MLP → легче понять attention/transformer
Но LLM требуют масштаб, данные, GPU, tokenizer, контекст
Локальные маленькие модели — хороший полигон для понимания архитектуры


 = Термины, которые стоит различать:
pretraining		# обучение на больших данных с нуля
fine-tuning		# дообучение готовой модели
LoRA			# низкоранговые адаптеры, меньше памяти
prompting		# изменение входа без изменения весов
distillation		# перенос знаний в меньшую модель
quantization		# квантизация весов для экономии памяти
inference		# генерация/предсказание без обучения



	--- ЗОЛОТЫЕ ПРАВИЛА ---
 = Помни:
- Всё обучение — это подбор весов через ошибку
- Один параметр — один вес
Много параметров — сеть
- Сначала baseline, потом модель
- Сначала простая модель, потом сложная
- Данные важнее архитектуры
- Метрика должна соответствовать задаче
- Train/val/test split обязателен
- Не верь accuracy при дисбалансе
- Loss без метрики бессмысленна
- Воспроизводимость: seed, версии, конфиги
- Если не сходится, ищи в данных, lr, признаках, коде
- ИИ не магия: он повторяет закономерности, а не понимает смысл
- Если задача решается if/else — не усложняй
- Если данных нет — сначала собери или смоделируй
- Если модель большая, а данных мало — почти гарантированное переобучение
